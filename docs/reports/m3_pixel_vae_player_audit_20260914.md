# M3 Pixel VAE 玩家重建上限审计（2026-09-14）

## 结论

当前冻结的 PERSIST/2DAction Pixel VAE 虽未针对本项目玩家训练，但在真实
PLOT 验证帧上的编解码没有造成系统性的额外身份丢失。现阶段不应替换 VAE；
应先修复 M3 对人物参考条件不敏感的问题。

## 协议

- 数据：`val_id_c65.pt` 中固定随机种子 0 抽取的 64 个有效窗口。
- 每个窗口选择其他玩家可见像素最多的帧；可见区域至少 96 像素。
- 路径：真实 RGB → 冻结 Pixel VAE posterior mean → 冻结 Pixel VAE decoder。
- M3 完全旁路，因而结果只衡量 codec 的重建上限。
- 人物误差使用真实 instance mask；身份指标使用冻结的 PLOT 玩家身份编码器。
- VAE：`640×360 → 16×36×64`，空间压缩倍率为 10。

全帧 L1 为 0.0165，背景 L1 为 0.0161。玩家区域误差略高，但没有出现相对
背景数量级更大的退化。绝对身份 top-1 本身只有 56.3%，说明验证窗口包含难以
区分或相似的皮肤，且身份编码器并非完美评估器。因此主要看同一样本编解码前后
的配对变化：身份余弦为 0.9938，top-1 没有下降。

## 决策

1. 第一版简化 M3 继续使用当前 VAE，避免废弃已有 M3/M4 latent 接口和 checkpoint。
2. 先实现单一 reference-token 外观路径，并用打乱/置零参考条件验证输出确实依赖外观。
3. 在把透明四视图变成 VAE reference tokens 前，另做一次 canonical RGBA reference
   canvas 的编解码审计；本报告验证的是画面内玩家的输出上限。
4. 只有在新的条件路径已经生效、且真实帧 codec 上限被证明限制人物指标时，才比较
   8 倍空间 VAE。不要直接换用带时间压缩的 video VAE。
