# PLOT 评测方案 v0.3（2026-09-05）

采集计划以 [data.md](data.md) v0.5 与 [data_plan.json](data_plan.json) 为准，四模型名称、输入输出
和闭环顺序以 [method.md](method.md) 为准。主训练十种 S 场景不变；普通 val/test 沿用训练生成
逻辑，世界来源独立。本轮不做距离测量、距离扫描、冷却边界或规则变体探针。

## 1. 数据分工

| 数据 | 内容 | 用途 |
|---|---|---|
| val-ID | Core 1,500 / Release 3,000 条，同训练场景配比 | 日常调参、选 checkpoint |
| test-ID | Core 1,500 / Release 3,000 条，同训练场景配比 | 普通场景总体性能 |
| E-Representative | val 各 S 场景 10 条，共 100；test 各 50，共 500 | 在完整场景中评世界转移、渲染和策略；不重采 |
| 独立受控 eval | 220 dev + 1,100 test 条，80/400 根场景 | 诊断多人事件转移与归因 |

代表性子集已包含在普通 val/test 中，报告等场景宏平均，不与完整 test 作为独立样本合并。所有最终清单在看模型结果前固定，dev 与最终 root/world 来源互斥。

## 2. 普通 test：训练逻辑生成的轨迹

- TF：真值状态加联合动作，测下一步/块的事件 P/R/F1、来源目标准确率、方块和角色状态误差。
- Rollout：只给初态和记录的联合动作，NPC 动作也回放；连续预测后测中间/最终方块差异、血量误差及角色状态漂移。各时间点只统计长度足够的轨迹并报分母。
- 渲染：记录画面是否忠实呈现预测状态。世界状态错与渲染漏画分开；PSNR/LPIPS/FVD 为辅助，不代替事件准确率。
- 结果按 S01–S10、2/3/4 槽位、无/有 NPC 分层，普通 test 按实际采集配比汇总；不将同生成逻辑的新种子称作任务族 OOD。

## 3. 受控 eval

| 组 | dev / test 根场景 | 分支数 | dev / test 轨迹 | 指标 |
|---|---|---:|---|---|
| E-Relay | 20 / 100 | 2 | 40 / 200 | 每次挖放后的状态、source/target、最终结构差异 |
| E-Unseen | 20 / 100 | 2 | 40 / 200 | 视野外更新累计、最终状态、返回后的画面忠实度 |
| E-Joint | 20 / 100 | 4 | 80 / 400 | 各角色动作响应、漏更新、错误更新、无动作变化 |
| E-Hit（补充） | 20 / 100 | 3 | 60 / 300 | 受伤角色、攻击来源、旁观者误伤、状态/事件/画面一致 |

E-Relay 交换放置者/挖掘者职责；E-Unseen 对照转头期间编辑/不编辑；E-Joint 对照仅 A/仅 B/两人/无人编辑；E-Hit 对照 A 打 B/C 打 B/无人攻击。详细采集条件见 data.md 第 5 节。

全部采用稳定可执行动作。攻击角色固定在明显可命中的位置，留充分动作间隔，不测临界距离、冷却边界或精细击退距离。无动作/无人攻击分支提供错误变化对照。

每局检查中间状态，不只检查最终结构，防止错误相互抵消。事件按时间、来源、操作、目标匹配；严格匹配为主，任何时间容差在 dev 冻结且所有方法一致。所有分支按 root 组配对统计，不将重复视角/分支当独立样本。

## 4. 基线与贡献证据

主要比较同样具有显式持久状态的模型：PLOT 事件模型 vs 复制旧状态并预测变化的状态基线。B2 应保留复制/残差能力，不故意让其重建所有不变格子。共享状态带来的基本保持与事件预测收益分别解释。

B1 Pixel 是内部纯像素参照，不冒充 Solaris 复现；视觉指标尽量同协议，但不同初始化权限分赛道。探针只用 train 学、val/eval-dev 校准，test 报测量误差。

共享头 vs 独立头均从同一无攻击预训练主干开始，用 train 固定嵌套攻击子集，报正事件、负尝试、轨迹数和预算；最终在 E-Hit 测归因，普通 test 战斗行验证自然分布效果。不能提前完整攻击预训练再声称小样本。

## 5. 文字 agent 与 NPC 闭环

E-Representative 中有 B 的场景测文字任务完成率和目标结构 IoU；有 N/H/G 的场景测对应行为与实际事件后果。角色的行为模式来自已记录标签或校准评测器，不由模型自报即算正确。按钮用 F1，鼠标连续量用单独误差。

动作相同而仅控制来源标签变化，只是接口检查。策略自己产生动作后分布会改变，不要求事件 F1 与专家回放相等，也不再对齐原专家后续状态。保存新动作，在同初态引擎重放；模型内成功和引擎可执行性分别报告。新 rollout 属于评测输出，不增加采集数、不回灌正式 train。
